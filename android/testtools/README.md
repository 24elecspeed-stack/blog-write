# TEST-01 전체 글·사진 테스트판

- 앱 이름: 키워드 리서치 TEST-01
- 패키지: com.keyword.research.headingtest (정식 앱과 동시 설치)
- 버전: 2.59-TEST-01. 정식 버전 번호는 올리지 않음.
- 빌드: android 폴더에서 `gradlew.bat :app:assembleHeadingTest`
- APK: app/build/outputs/apk/headingTest/app-headingTest.apk

## 사용하는 방법

1. 테스트 APK를 설치한다. 기존 앱의 API 키와 설정은 별도 앱에 자동 복사되지 않는다.
2. 접근성 설정에서 **글·사진 전체 배치 TEST-01**만 테스트에 사용한다. 기존 앱 배치를 동시에 시작하지 않는다.
3. 네이버 블로그 앱에서 새 빈 원고를 연다.
4. 테스트 앱 상단 **TEST-01 · 샘플 시험**을 누르고 **전체 샘플 시작**을 누른다.
5. 한글 제목, 도입, 소제목 2개, 본문 2개, 사진 2장의 흐름을 확인한다. 이 샘플에는 API 키가 필요 없다.
6. 실제 원고는 기존 **블로그 반자동 복사** 화면에서 글과 사진을 준비해 시험한다.

## 입력 후 서식 변경 방식으로 수정

글과 사진은 기존 붙여넣기 순서로 입력하며, 입력 중에는 서식 메뉴를 열지 않는다.
마지막 입력 후 아래쪽 소제목부터 역순으로 찾아 해당 텍스트만 선택하고 크기 19와 굵게를 적용한다.
선택 범위가 소제목과 일치하는지 매번 확인하며, 일치하지 않으면 원고를 남겨두고 서식 처리를 중지한다.
사진 접근성 노드 개수로 중단하던 테스트판 검사는 제거했다. 사진 성공을 보장하는 변경은 아니다.

## 검증 결과와 한계

2026-09-24 Pixel_7 / emulator-5582의 네이버 블로그 앱에서 실제 접근성 서비스를 실행했다.

- 제목 입력칸과 본문 입력칸 분리, 한글 텍스트 입력 확인.
- 최종 APK로 입력 종료 후 두 소제목의 선택 범위와 크기 19·굵게 적용 로그를 확인. 실제 화면에서도 두 소제목만 커지고 굵어졌으며 본문은 유지됐다. 증빙: 저장소 루트의 post-format-final.png. 입력 도중 서식 전환은 하지 않는다.
- 사진 URI의 ACTION_PASTE가 true를 반환했지만 사진 2장은 실제로 나타나지 않았다. **전체 글·사진 테스트 성공이 아니다.** 사진 다음 서식도 실제 사진이 삽입된 조건에서는 아직 검증되지 않았다.
- 기존 흐름으로 되돌린 뒤에도 에뮬레이터에서 사진은 나타나지 않았다. 사진 업로드 문제는 별도 미해결이며, 완료 안내에서도 사진 누락을 확인하도록 안내한다.
- `MoveBelowImage`는 기존 반자동 동작이다. 사진 아래 새 본문을 사용자가 누르는 단계가 남아 있다.
- 입력 후 서식 처리에 실패해도 이미 입력된 원고를 삭제하거나 다시 붙여넣지 않는다.
- 사진 실패 원인과 사용자 휴대폰에서의 실제 동작은 추가 검증이 필요하다. 게시글 저장·발행은 자동 실행하지 않는다.

## 자동 시험 보조 스크립트

`start-heading-test.ps1`은 에뮬레이터 전용이다. TEST-01 제목인 시험 원고만 닫고 새 원고를 연 뒤 테스트 APK 설치, 접근성 연결, 샘플 시작을 수행한다. `HeadingTest` logcat과 실제 네이버 화면을 함께 확인해야 한다. 단순 붙여넣기 반환값을 사진 성공 판정에 사용하지 않는다.

커밋과 GitHub 푸시는 사용자가 요청할 때만 진행한다.

## 마지막 문단 배치 재시험

2026-09-24 재로그인한 emulator-5582에서 두 방식으로 전체 샘플을 실행했다.
샘플은 두 번째 사진 뒤에 마지막 본문을 입력하도록 수정했다.

- 기본 FileProvider URI: 마지막 본문 입력과 후처리 소제목 두 개의 19·굵게 로그는 확인됐지만 사진 두 장 모두 보이지 않았다.
- `start-heading-test.ps1 -GalleryUri`: 시스템 MediaStore 사진 주소로 비교했으나 사진 두 장 모두 보이지 않았다. 마지막 본문과 소제목 후처리는 실행됐다.
- 갤러리 비교 시험은 Pictures/KeywordTest에 합성 시험 사진을 만든다. 실제 사용자 사진을 사용하지 않는다.
- 따라서 실제 사진 다음에 마지막 문단이 놓이는지는 아직 검증하지 못했다. 사용자 휴대폰의 마지막 사진 위치 문제가 해결됐다고 판단하면 안 된다.
- RichCopyTestActivity의 입력 순서를 추측으로 바꾸었던 수정은 사용자 정정 후 되돌렸다. 원래 v2.67 앱에서 글은 전부 들어가고 사진만 뒤로 가는 증상을 먼저 재현해야 한다.
