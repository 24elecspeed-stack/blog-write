1. 만들어진 것

코드는 이미 다 작성되어 있고, 켜고 끌 수 있게 만들어뒀습니다.

기기 1대 = 키 1개 완료

앱을 처음 열면 라이선스 키 입력 화면이 뜨고, 그 키는 그 폰에만 등록됩니다. 같은 키를 다른 폰에 넣으면 거부됩니다.

LicenseGate.kt · LicenseActivity.kt

온라인 회수 완료

관리자 웹페이지에서 키를 "회수"하면, 그 키를 쓰던 폰은 다음 실행 때(또는 일정 주기로) 확인해서 스스로 잠깁니다.

GitHub 중계 + 항상 온라인 필수 완료

앱은 매번 실행될 때 GitHub의 작은 파일 하나를 먼저 확인합니다. 이 파일을 못 읽으면(오프라인 포함) 실행이 안 됩니다 — "언제나 온라인이어야 실행"이라는 요구사항입니다. 이 파일의 스위치 하나로 전체 서비스를 한 번에 켜고 끌 수도 있습니다.

license-status.json

PHP + MySQL로 작성됨. 브라우저로 여는 관리 화면(admin.php)에서 키 생성·조회·회수·기기 해제를 전부 처리합니다. 키 형식은 옛날 시리얼 번호 스타일(A7K9M-3PQXZ-8DFRT-2WNBV)입니다.

3. 보안 관련 질문·답변 정리

"소스 유출 막을 수 있나" 관련해서 나눈 이야기 요약.

APK를 AI로 디컴파일해서 소스를 통째로 가져올 수 있나?

가능하다. 화면(XML)은 100% 복원되고, 코드는 변수명·주석만 사라진 채 로직은 거의 그대로 읽힘. 단, 서버 쪽 코드(PHP·DB·관리자 비밀번호)는 APK 안에 없어서 이 부분은 절대 못 가져감.

소스를 아예 못 열어보게 막을 수 있나?

완전히는 불가능. 폰에서 실행되려면 코드가 폰 안에 있어야 하고, 실행되는 이상 최소 기계어 수준으로는 항상 꺼내볼 수 있음 — 모든 로컬 실행 앱의 근본적 한계.

그럼 뭘 할 수 있나?

"보기 어렵게"는 확실히 가능 — ProGuard/R8 난독화(무료, 변수명을 a/b/c로 뭉갬)를 켜면 훨씬 어려워짐. 지금은 꺼져 있는 상태(디버그 빌드라). 결정 대기

플레이스토어에 올려서 APK 파일 자체가 안 돌아다니게 하면 낫지 않나?

배포 경로 통제엔 도움되지만, 설치된 뒤엔 여전히 추출 가능해서 근본 해결책은 아님. 게다가 이 앱이 쓰는 "네이버 반자동 배치" 접근성 기능은 플레이스토어 심사에서 거의 항상 거부되는 종류라 이 앱엔 플레이스토어가 안 맞을 가능성이 높음.

그럼 대안은?

이미 만든 라이선스 키 시스템과 자연스럽게 이어지는 "키 입력해야 다운로드되는 비공개 페이지"를 24elecspeed.com에 만드는 방법을 제안함. 착수 전
